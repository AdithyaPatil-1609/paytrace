# Local merchant identification

The account dashboard first checks the maintained merchant dictionary. For an unknown merchant, the existing spelling matcher supplies a possible catalog candidate. A bounded background Qwen/Ollama job then suggests a recognizable business name and category, including for names outside the dictionary. Its input contains only normalized merchant names (not amounts, accounts, raw emails or user IDs).

The result is stored on the signed-in user's `LiveMerchant` in the main Neo4j database. Payment details let the account owner confirm or reject it; an unconfirmed suggestion remains in Issues. Confirming affects presentation and classification, not the original transaction, grouping key, shared catalog or cancellation instructions. No provider links or cancellation instructions are generated by this model.

## Run locally

1. Start the existing Ollama server with `qwen3:14b` available (or use an already configured `PAYTRACE_CHAT_MODEL`). The backend must be able to reach the model. `PAYTRACE_OLLAMA_URL` defaults to `http://127.0.0.1:11434`; the existing model client permits a private LAN address only when `PAYTRACE_ALLOW_LAN_MODEL=true`. Do not expose Ollama publicly.
2. `PAYTRACE_MERCHANT_AI_ENABLED=true` enables the background job (default); set `false` to disable it. This setting is independent of `PAYTRACE_EMAIL_AI_ENABLED`.
3. Run `npm run dev`. Sign in, visit All payments and wait for the account dashboard's next refresh. Existing unknown recurring merchants are considered automatically, so no reimport is required. Open payment details to review a suggested identity.
4. `npm test` and `npm run typecheck` verify the code. The AI tests use deterministic mock model responses, not a live model.

If Ollama is not reachable, existing dictionary and recurring payment discovery still work. The background job backs off and retries later without blocking account responses.

## Same-day recurring amounts

When two or more records share a date for the same merchant and account, the recurring engine measures the gap between distinct cycle dates and uses the combined amount on each date. Individual evidence remains intact. For ₹1,000 + ₹250 on 30 August, and ₹1,000 + ₹250 on 29 September, the reported cycle is ₹1,250/month with a ₹15,000 annual projection. The engine does not infer separate mandates or a price rise from mixed component amounts. Scheduled notices remain unconfirmed until a corresponding debit is found.
